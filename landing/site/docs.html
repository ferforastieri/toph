Instalar o Toph Guia para agentes de IA

Comece aqui #

Toph é um workbench de agentes de IA self-hosted. Você abre um projeto, cria um ou vários Tophs e cada um trabalha com o motor, o modelo, as ferramentas e as permissões que você escolher. O projeto e os arquivos ficam no seu computador ou servidor.

Um Toph ou um time

Uma tarefa pode ter um Toph sozinho ou vários. Sem menção, o roteador escolhe quem responde; com @handle, você escolhe.

O projeto é o centro

Arquivos, editor, terminal, Git, bancos, debug e previews no mesmo lugar. O agente trabalha no projeto de verdade.

Você manda nas ferramentas

Plan, Ask ou YOLO por Toph. Aprovações aparecem dentro da tarefa antes de escrever, apagar ou rodar algo.

Seu modelo, seu motor

OpenCode, Claude Code ou Codex. OpenAI, Anthropic, DeepSeek, OpenRouter, Ollama ou o gateway da sua empresa.

Requisitos

  • Linux x86_64/arm64 para o servidor; Mac, Linux ou Windows para o app desktop.
  • Porta 8787 livre (ou outra definida em TOPH_ADDR).
  • Git e, para editar o código, Node/pnpm e Rust. O instalador Linux pode instalar o toolchain de desenvolvimento.
  • Uma conexão de modelo (API key, gateway ou Ollama local) para os Tophs responderem.

Instalar #

Linux em uma linha

$ curl -fsSL https://github.com/ferforastieri/toph/releases/latest/download/install.sh | sudo sh

O instalador baixa o binário, cria o usuário de serviço, grava /etc/toph/toph.env e ativa o systemd. No fim, abra http://localhost:8787 e entre com a senha de admin mostrada pelo instalador.

$ sudo systemctl status toph
$ sudo journalctl -u toph -f
$ curl -fsS http://127.0.0.1:8787/api/health

Docker

git clone https://github.com/ferforastieri/toph.git
cd toph
TOPH_ADMIN_PASSWORD='troque-esta-senha' docker compose -f deploy/compose.yaml up -d

Do código-fonte

git clone https://github.com/ferforastieri/toph.git
cd toph
make build          # builda o web e o binário em bin/toph
sudo install -m 755 bin/toph /usr/local/bin/toph

Para desenvolvimento: make dev sobe a API e o app web separados. O binário embute o frontend de web/dist; rode npm run build em web/ antes de buildar o backend se alterar a interface.

Configurar #

O serviço lê /etc/toph/toph.env (ou as variáveis do docker compose). As principais:

VariávelPara que serve
TOPH_ADDREndereço e porta. Padrão 0.0.0.0:8787.
TOPH_DATA_DIRBanco SQLite, chave mestra e artefatos. Padrão /var/lib/toph.
TOPH_WORKSPACESPastas permitidas para projetos. Padrão /srv/toph/workspaces.
TOPH_ADMIN_PASSWORDSenha inicial do admin (só é usada no primeiro boot).
TOPH_SECURE_COOKIEStrue atrás de HTTPS; false em HTTP local.
TOPH_TRUSTED_PROXIESIP/CIDR do proxy reverso, para ler X-Forwarded-For.
TOPH_FIREBASE_CREDENTIALS_FILEOpcional: login Google/Firebase.
TOPH_FIREBASE_PROJECT_IDOpcional: projeto Firebase.
TOPH_BUILD_IDIdentificador da build exibido em /api/version.
Proxy reverso: encaminhe / e /api/* para a porta do Toph. downloads, SSE e WebSockets precisam passar. Se usar HTTPS, mantenha TOPH_SECURE_COOKIES=true.

Primeiro Toph #

  1. Conecte um modelo. Abra Configurações → Conexões, escolha o provedor, informe a URL/base e a API key. Para Ollama, use a URL local. O teste mostra os modelos disponíveis.
  2. Adicione um projeto. Use o botão + no topo: ele lista todos os repositórios Git encontrados nas pastas permitidas. Se o repo ainda não for um projeto, o Toph cria e abre na hora.
  3. Crie um Toph. Em Novo Toph, escolha um perfil (Toph, Leo, Nico, Nova, Bia, Pia, Atlas, Rafa) ou comece do zero. Ajuste nome, handle, papel, prompt, modelo, motor, esforço e ferramentas.
  4. Escolha as permissões. Plan só lê e propõe; Ask pede aprovação antes de mexer; YOLO executa o que foi permitido sem interromper.
  5. Abra uma tarefa e escreva. Você pode mencionar @handle, anexar imagens/arquivos ou usar áudio. O histórico fica na tarefa.

Tophs e grupos #

Cada tarefa tem um ou mais Tophs. Uma mensagem sem menção passa pelo roteador: ele escolhe de 0 a 2 Tophs, ou todos quando você pede para o grupo. Uma menção explícita (@leo) sempre vence e seleciona aquele Toph.

  • Um Toph sozinho: sessão, contexto e histórico próprios.
  • Vários Tophs: cada um roda na própria sessão, com o histórico compartilhado da tarefa. Um pode chamar o outro com delegate ou mencionar @handle.
  • Ninguém precisa responder: um agradecimento ou recado pode ficar sem resposta; a mensagem continua registrada.
  • Nova mensagem durante uma execução: o Toph cancela a execução anterior, espera ela fechar e insere a nova mensagem abaixo da última saída.

Motores #

O motor conduz o loop do agente; o Toph entrega contexto, ferramentas, permissões e aprovações. Cada Toph pode usar um motor diferente no mesmo projeto.

OpenCode

Roda localmente com o modelo e o provedor escolhidos. É o motor mais testado com o gateway de ferramentas do Toph.

Claude Code

Usa a assinatura Claude que você já tem, com o gateway Toph como ferramenta.

Codex

Sandbox isolado, com o gateway Toph como única fonte de ferramentas.

Outros CLIs

Cursor, Grok, Gemini e Pi aparecem para instalar/testar, mas o runtime ainda não está ligado.

Em Configurações → Harness você instala, testa e atualiza cada CLI. O OpenCode precisa ser 2.2.6 ou mais recente: versões antigas perdem as ferramentas MCP na primeira resposta.

Ferramentas e permissões #

As ferramentas são do Toph, não do projeto inteiro. Você escolhe o que cada um pode ler, escrever, rodar e acessar.

  • Arquivos e shell: ler, criar, editar, apagar e rodar comandos no projeto. O agente mostra o comando e a saída.
  • Aprovações: no modo Ask, o Toph para antes de uma ação que muda o projeto. Você autoriza uma vez, sempre ou recusa.
  • Perguntas: o agente pode pedir uma decisão no meio da tarefa; a pergunta aparece no chat.
  • MCP: conecte servidores em Configurações → Conexões → MCPs e selecione quais cada Toph pode usar. O agente lista as ferramentas com mcp_list e chama com mcp_call.
  • Skills: receitas aprovadas para tipos de tarefa. O Toph lê a skill com read_skill e pode propor novas.
  • Memória: fatos duráveis do projeto, consultáveis por search_memory.
  • Modelos por Toph: modelo, provedor, esforço e temperatura podem ser diferentes em cada Toph.

Workbench #

O projeto é o centro, não o chat. O workbench tem:

Explorer e editor

Árvore de arquivos, busca, edição, criação, upload e download. Arquivos grandes são baixados em streaming.

Source Control

Status, diffs, stage, commit, branches, blame e descarte de mudanças.

Terminal

Terminais reais no servidor, por projeto, para rodar o que precisar.

Bancos de dados

Conexões Postgres, MySQL e SQLite, schema e consultas com resultado.

Debug

Sessões de depuração, breakpoints, console e variáveis para Node, Python e outros runtimes.

Web apps e previews

Rode a aplicação e abra o preview no painel, com logs e inspeção.

Arquivos, imagens e áudio #

  • Imagens: arraste para o input ou use o botão de anexo. O OpenCode recebe o arquivo de verdade via --file e o modelo vê a imagem.
  • Limites: até 6 anexos e 8 MB no total por mensagem. O servidor aceita um corpo de até 32 MB.
  • Outros arquivos: PDF, texto, Markdown, JSON, CSV e logs são aceitos; binários precisam ser UTF-8 ou imagem.
  • Áudio: grave pelo microfone; se o navegador transcrever, o texto entra no input; senão o áudio fica como anexo.
  • Downloads: a aba de arquivos baixa qualquer tamanho com streaming e Content-Disposition: attachment.

Projetos e repositórios #

  • Pastas permitidas: em Configurações → Workspace, adicione as raízes que o Toph pode ler e escrever. O servidor não sai dessas pastas.
  • Botão +: lista os projetos existentes e todos os repositórios Git das raízes. Clicar em um repo ainda não aberto cria o projeto e abre.
  • Vários projetos: abra quantos quiser; cada um tem suas tarefas, terminais e configurações.
  • Fechar projeto: encerra terminais/debug daquele projeto sem apagar os arquivos.

Atualizar #

  • CLIs: Configurações → Harness tem o botão de atualizar em cada motor instalado (OpenCode, Claude Code, Codex). O OpenCode roda opencode upgrade.
  • Toph: o instalador cria um updater; releases novas aparecem no app. Para atualizar manualmente, rode o instalador de novo.
  • Depois de atualizar o frontend: um Ctrl+Shift+R garante o bundle novo.

Solução de problemas #

O agente não tem ferramentas / só aparece “skill”

Atualize o OpenCode para 2.2.6+ em Configurações → Harness. Versões antigas montam a lista de ferramentas antes do MCP conectar.

MCP não lista

Confira se o servidor está selecionado no Toph e se o token não expirou. O erro 401 significa token inválido; 404/“not selected” significa que o nome/id não pertence àquele Toph. Use o nome exato mostrado no prompt.

Enviar imagem não faz nada

Atualize o app e dê Ctrl+Shift+R. O limite é 8 MB no total; acima disso a mensagem mostra um erro. A rota aceita 32 MB de corpo.

Download “não disponível”

O Toph faz streaming de qualquer tamanho. Se estiver atrás de um proxy, ele precisa encaminhar /api/projects/*/raw e não bufferizar a resposta.

Login/API 401 atrás de HTTPS

Use TOPH_SECURE_COOKIES=true e configure TOPH_TRUSTED_PROXIES com o IP do proxy. O cookie é SameSite=Strict.

Porta ocupada

Veja ss -ltnp | grep 8787 e ajuste TOPH_ADDR para outra porta.

Para agentes de IA #

AI-friendly: esta seção foi escrita para ser executada por um agente. Use os comandos exatos, verifique cada passo e não invente caminhos. Uma versão em Markdown está em docs.md e o resumo para LLMs em llms.txt.

Objetivo

Instalar o Toph em um servidor Linux x86_64/arm64, configurar a porta e a pasta de projetos, subir o serviço e verificar /api/health.

Passos (Linux, root)

# 1. instalar o binário e o serviço
$ curl -fsSL https://github.com/ferforastieri/toph/releases/latest/download/install.sh | sudo sh -s -- --no-components

# 2. revisar a configuração (o instalador já criou)
$ sudo sed -n '1,120p' /etc/toph/toph.env

# 3. subir e habilitar
$ sudo systemctl enable --now toph

# 4. verificar
$ curl -fsS http://127.0.0.1:8787/api/health
$ curl -fsS http://127.0.0.1:8787/api/version

Configuração mínima esperada

TOPH_ADDR=0.0.0.0:8787
TOPH_DATA_DIR=/var/lib/toph
TOPH_WORKSPACES=/srv/toph/workspaces
TOPH_ADMIN_PASSWORD=<senha-forte>
TOPH_SECURE_COOKIES=false   # true atrás de HTTPS
TOPH_TRUSTED_PROXIES=        # IP do proxy, se houver

O instalador imprime a senha de admin gerada. Ela só é usada no primeiro boot; para redefinir, pare o serviço e remova o usuário admin do banco ou use a tela de login/recuperação conforme a versão.

Verificação de saúde

  • GET /api/health deve retornar {"ok":true,...}.
  • GET /api/version deve retornar a versão/build.
  • O frontend fica em /app; o login usa cookie toph_session.
  • Os dados ficam em TOPH_DATA_DIR/toph.db; a chave mestra em TOPH_DATA_DIR/master.key. Faça backup dos dois juntos.

Prompt pronto para uma IA

Instale o Toph neste servidor Linux seguindo https://tophs.vira.ia.br/llms.txt e https://tophs.vira.ia.br/docs.md.
Requisitos: root/sudo, porta 8787 livre, pasta de projetos em /srv/toph/workspaces.
Execute a instalação, ajuste /etc/toph/toph.env, suba o serviço e valide /api/health e /api/version.
Não invente caminhos; se um comando falhar, mostre a saída e pare.
No fim, diga a URL, a versão e onde ficam o banco e a chave mestra.

Documentation

Toph, in one page.

Toph is a self-hosted workbench for a homelab. It combines a code editor, a database console, OpenCode sessions, a terminal and web app tabs in one workspace. The same Go backend serves the browser client and the Android APK.

This page is intentionally plain, semantic and machine-readable. For a compact agent-oriented summary, see /llms.txt.

What Toph is

  • A single-tenant, self-hosted application. There is no hosted account or vendor backend.
  • A client-server system: files, shells, database drivers, credentials and AI sessions live on the server.
  • A workbench with tabs: editor, database, AI, terminal and web app.
  • Available as a browser app and as a real Android APK.

Toph is not a multi-tenant SaaS, not a VS Code fork, and not a DBeaver replacement with every database feature. It is a focused homelab workbench that runs where your repositories and services already are.

Architecture

Browser (React)                 Android (Kotlin/Compose)
        │                                   │
        └────────── HTTPS / WSS ────────────┘
                          │
                      toph (Go)
        ├── auth, sessions, CSRF
        ├── projects and workspace files
        ├── search and git status
        ├── PTY terminal
        ├── SQL + NoSQL database gateway
        ├── OpenCode proxy
        └── web target registry

The server owns the credentials and the processes. Clients are thin. The web build is embedded in the Go binary; the Android app connects to the same API.

Requirements

  • Linux server, VM or LXC. macOS works for development.
  • Go 1.26+ to build from source.
  • Node.js 22+ for the web client.
  • Docker Engine and Compose v2, or a single Go binary.
  • Android 8.0+ (API 26) for the APK.
  • Optional: an OpenCode server for AI sessions.

One-command install

curl -fsSL https://github.com/ferforastieri/toph/releases/latest/download/install.sh | sudo sh

The installer supports Debian/Ubuntu and creates a systemd service, a toph user, the data directory, the workspace directory and the first admin password.

Install with Docker

git clone https://github.com/ferforastieri/toph.git
cd toph

TOPH_WORKSPACES_HOST=/srv/workspaces \
TOPH_ADMIN_PASSWORD='choose-a-strong-password' \
docker compose -f deploy/compose.yaml up --build

Open http://127.0.0.1:8787/app. The Compose file publishes the port only on localhost by default. Put Caddy, nginx or Tailscale in front for remote access.

Permissions: the container runs as UID 1000. The mounted workspace and the toph-data volume must be writable by that UID.

Install as a binary

make build
TOPH_WORKSPACES=/srv/workspaces \
TOPH_ADMIN_PASSWORD='choose-a-strong-password' \
./bin/toph

make build builds the web client, embeds it into the Go binary and writes bin/toph.

Android APK

Download the signed APK from GitHub Releases. Debug APKs are not published. On first launch, enter the Toph server URL, username and password. Use LAN, VPN or Tailscale.

Release builds are signed in CI from the repository's Android keystore secrets. Local development builds use ./gradlew assembleDebug and are not distribution artifacts.

Projects

A project is a directory on the server. The path must exist and be inside one of the configured workspace roots. Toph stores project metadata, per-user layout, database connections and web targets in SQLite under the data directory. It does not copy or modify the project directory except when you edit and save a file.

Editor and files

  • Web: Monaco, the editor engine behind VS Code.
  • Android: CodeMirror 6 in a local WebView, optimized for touch and IME.
  • File tree, search with ripgrep, git status and atomic saves.
  • Save conflicts are detected by content hash; Toph refuses to overwrite a file changed on disk.

Databases

Database credentials are encrypted with AES-GCM using a master key stored with mode 0600. Clients never receive the DSN. A profile can be marked read-only.

SQL drivers

PostgreSQL, MySQL/MariaDB, SQLite, SQL Server, Oracle, ClickHouse, Cassandra, Elasticsearch and Neo4j.

The SQL console accepts ordinary SQL. DDL, DML, transactions, EXPLAIN and cancellation are supported by the backend drivers.

MongoDB

The MongoDB console accepts a JSON query:

{
  "database": "app",
  "collection": "users",
  "filter": {},
  "limit": 100
}

Use pipeline instead of filter for an aggregation pipeline.

Redis

The Redis console accepts commands:

GET session:42
HGETALL user:1
SCAN 0 COUNT 100

Cassandra, Elasticsearch and Neo4j

Cassandra uses CQL. Elasticsearch accepts JSON with an index and body. Neo4j accepts Cypher.

Cassandra     SELECT * FROM keyspace.table LIMIT 100;
Elasticsearch {"index":"logs-*","body":{"query":{"match_all":{}},"size":100}}
Neo4j         MATCH (n:User) RETURN n LIMIT 100;

Editing rows

Opening a SQL table from the schema tree creates a table tab. If the table has a primary key and the profile is not read-only, each result row has edit and delete actions. Updates use the primary-key columns in the WHERE clause.

OpenCode

Toph proxies the OpenCode HTTP API and renders a native chat in both clients. Sessions are created with the project root as their working directory. The chat streams text, tool calls and permission requests; approve once, always or reject.

Run OpenCode on the same host or make it reachable from the Toph container, then set TOPH_OPENCODE_URL and, when required, TOPH_OPENCODE_AUTH. Toph does not run an AI model inside the phone.

Web app tabs

Web apps are just URLs stored on the server. Android opens them in a native WebView. The browser opens them in an iframe inside a workbench tab, with an external-open fallback for apps that block framing.

Updates

Web

The web client polls /api/version. When the server build ID changes, a toast appears; clicking it clears browser caches and reloads the current build.

Android

The APK checks the latest GitHub release. When a newer release contains an APK, Toph shows an update toast; clicking downloads the APK and opens the Android installer. Android always requires the final install confirmation. Release builds are signed when the Android keystore secrets are configured; otherwise the workflow fails rather than publishing a debug APK.

To publish an update, create a GitHub release with a tag such as v0.2.0 and attach an APK asset.

Security

  • Bind Toph to localhost, a LAN or a VPN. Never expose it directly to the internet.
  • Put TLS in front, for example Caddy or Tailscale HTTPS.
  • Use a strong password. Login is rate-limited; sessions are opaque tokens stored as hashes.
  • Database credentials stay on the server and are encrypted at rest.
  • Treat Toph as remote administration: it can read repositories, open shells and reach databases.
  • Project paths are restricted to configured roots, with symlink escape checks.

Troubleshooting

Toph starts but has no projects

Check TOPH_WORKSPACES. It is a colon-separated list of existing directories. Create a project from the app with a path inside one of those roots.

OpenCode is offline

Check TOPH_OPENCODE_URL, the OpenCode password and TOPH_OPENCODE_AUTH. The proxy is authenticated; the browser never talks to OpenCode directly.

The Android app cannot connect

Use the exact server URL reachable from the phone, including the port. For self-signed HTTPS, install the CA on the device or use Tailscale HTTPS.

A database profile fails

Test the DSN from the server first. Toph opens connections from the container or host running the Go process, not from your laptop.
